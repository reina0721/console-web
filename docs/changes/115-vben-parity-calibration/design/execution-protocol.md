# 后续单任务执行协议

本协议只适用于用户后续明确要求的产品实施。本次文档校准到此为止，不自动认领产品任务。

1. 读取 tmp、根与目标目录 AGENTS、docs/README 及相关 authority；读取本账本的研究、对应 VP 需求和 tasks。核对当前 HEAD，查全部消费者、聚合导出和既有测试；路径不存在时先纠正文档，不能按原提议盲建文件。
2. 只选择用户已要求、依赖满足且决策已明确的子项。优先恢复真实进行中的任务；待决策项跳过并报告，不擅自按默认值实现。连续模式也遵守这一条件，不把整份需求一概标为可执行。
3. 实施前按当时最新序号在 docs/changes 新建独立账本，具备 README、research、requirements、design、tasks；链接本 VP 来源。不要复用本次 115 校准序号，也不重新使用原 Task 114～119。
4. 使用待执行/进行中/待决策/受阻/验证失败/已完成等明确状态，并记录实际作用域。部分子项通过不能把整个 VP 勾为完成；报告未决原因和可独立推进项。
5. 先决定 Element/Variant/Composition/Pattern/Feature，再按依赖实现；不机械把所有 packages 当 Universal。公共能力须完成 [扩展门禁](README.md)，不得只写代码和单元测试。
6. 按需运行 pnpm codegen:plugins、pnpm codegen:design；先局部检查，再运行 pnpm check。完整脚本以 package.json 为准，含 build、performance、test:browser；不能省略后宣称通过。pnpm format 是全仓写操作，应仅格式化本次文件，避免无关改动。
7. 记录命令、退出码、最终源码版本、通过/失败范围及证据位置。失败须调查根因，不放宽边界/预算/视觉阈值。环境故障与实现失败分开记录；未实际运行、已中断或失败的门禁不得写通过。
8. 产品 DoD、浏览器/人工复核及所需门禁都完成后才记已完成；公共 API 同步相关 authority，历史证据留新账本。继续模式仅继续用户已要求且无待决策依赖的子项；需要用户决策时汇报具体选项，不自动改产品范围。
